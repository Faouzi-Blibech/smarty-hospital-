# Interface languages (Arabic, French, English) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every screen of the web app can be shown in English, French or Arabic, and the user picks the language from the interface.

**Architecture:**
- No i18n library. Messages live in typed namespace files under `web/src/i18n/messages/`.
  - Each file holds `en`, `fr` and `ar` objects. TypeScript fails the build if `fr` or `ar` is missing a key that `en` has.
- `I18nProvider` (client context) exposes `useT()`, which returns `{ t, lang, dir }`.
- Server components call `getT()`, which reads the `ward_lang` cookie.
- The root layout reads the same cookie, so `<html lang dir>` is right on the first paint (no flash and no hydration mismatch).
- `LanguageSwitcher` writes the cookie, updates the context, sets `<html lang dir>` and calls `router.refresh()` so server-rendered text follows.

**Tech Stack:** Next.js 16 App Router, React 19, strict TS, CSS Modules, `next/font/google` (Noto Sans Arabic).

**Spec:** No separate spec. The design decisions are in this header and the section below.

## Design decisions

- **Languages:** `en` (default, so today's demo is unchanged), `fr`, `ar`. Arabic is Modern Standard Arabic, written so a Tunisian reader finds it natural. Arabic sets `dir="rtl"` on `<html>`.
- **Persistence:** the `ward_lang` cookie (`path=/`, one year, `SameSite=Lax`). No account setting and no backend change.
- **Where the picker is:**
  - the sign-in / role picker page
  - the staff sidebar footer (doctor, nurse, admin)
  - the patient app header
- **Picker labels:** each language is written in its own script: `English`, `Français`, `العربية`.
- **Keys:** written as `namespace.key`, for example `t("doctor.summaryTitle")`.
  - Interpolation uses `{name}` placeholders: `t("waitlist.examsProgress", { done: 2, total: 3 })`.
  - No plural engine. Write strings so a count reads correctly for any number, e.g. "Exams: {done}/{total}" or "Open alerts: {n}".
- **Dates and times:**
  - The `lib/time.ts` formatters take an optional `lang`; the default is `"en"`.
  - Locales: `en-GB`, `fr-TN`, `ar-TN`. `ar-TN` uses Latin digits, which is what Tunisian hospitals use.
  - Clock times stay in 24 h.
- **Not translated:**
  - **Data:** patient and staff names, free text typed by people (notes, referral text), alert messages built by the backend, AI reasons and summary text from the API, and exam labels from the backend catalogue.
  - **Medical abbreviations:** NEWS2, SpO2, HR, BP, mg, bpm.
  - **IDs and bed codes.**

  Data written by people or the backend keeps `dir="auto"` where it already has it.
- **RTL:** layout CSS uses logical properties (`margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`, `border-inline-start`) wherever a left/right value would look wrong mirrored.
  - Charts (`VitalsChart`) and the NEWS2 strip stay left-to-right, because time runs left to right: wrap them in `dir="ltr"`.
  - Directional glyphs (`›`, `←`, `→`) are flipped in RTL with `.flip` (`:dir(rtl) .flip { transform: scaleX(-1) }`) or swapped by key.
- **Fonts:** Noto Sans Arabic moves from `PatientFrame` to the root layout. It's added to the end of `--sans` and `--serif` so Arabic glyphs render in every view.
- **Honesty copy:** when translating "simulated", "prototype", "AI suggestion" or "needs review", keep the same meaning. Never strengthen a claim (no "diagnosis", "certified" or "clinically validated").

## Global Constraints

- Only files under `web/` and `docs/` change. No backend or contract change.
- `npm run typecheck` and `npm run build` pass.
- No new npm dependency.
- English text stays exactly as it is today, apart from typo fixes.
- Every user-visible string literal in `web/src/components/**` and `web/src/app/**` goes through `t()`. The only exceptions are the ones listed under "Not translated" and the mock fixture data in `web/src/mocks/**`.
- No emojis in strings.
- `aria-label`, `title`, `placeholder` and `alt` texts are translated too.

## Review Focus

1. Arabic layout mirrors: in RTL the sidebar sits on the right, chevrons point the right way, and no text overflows its badge. The vitals chart time axis still runs left to right.
2. Switching language on a page with server-rendered text (the role picker, page headers) changes that text without a reload, because of `router.refresh()`.
3. Reloading keeps the chosen language. Opening a deep link in a new tab uses the cookie, with no flash of English.
4. French strings are often 30% longer than English. Buttons and pills must not clip: check the waitlist, the nurse board and the patient phone frame at 390 px wide.
5. Times and dates follow the language (`lun. 5 oct.` / `الاثنين 5 أكتوبر`), but the clock stays 24 h with Latin digits.

  - `web/src/lib/labels.ts`: urgency words, AI source, red flags and no-show words become key lookups.

**Interfaces (produced, used by every later task):**
- `type Lang = "en" | "fr" | "ar"`, `LANGS`, `DEFAULT_LANG = "en"`, `LANG_COOKIE = "ward_lang"`, `dirOf(lang): "ltr" | "rtl"`, `localeOf(lang)`: `en-GB` / `fr-TN` / `ar-TN`.
- `messages(ns)` in `define.ts`: `en` is the source; `fr` and `ar` must have exactly the same keys.
- `type Key`: a union of `"<ns>.<key>"` strings.
- `translate(lang, key, vars?)`: a missing key falls back to English, and then to the key itself.
- `useT(): { t(key: Key, vars?: Record<string, string | number>): string; lang: Lang; dir: "ltr" | "rtl"; setLang(l: Lang): void }`
- `getT(): Promise<{ t; lang; dir }>` (server only)
- Time helpers: `tunisDay(iso, lang?)`, `dayLabel(iso, ref?, lang?)`, `greeting(ref?, lang?)`, `ago(iso, ref?, lang?)`.
- Label helpers: `urgencyWord(u, t)`, `aiSourceLabel(source, t)`, `redFlagLabel(code, t)`, `noShowWord(prob, t)`.
  - They take a `t` function, so the files stay hook-free. `URGENCY[u].word` goes away; colours stay.
